# OligoArk physical DNA-storage pilot v1 — execution record

**Status (2026-10-09): PLANNED / SOFTWARE PREFLIGHT INSTRUMENTED. No wet-lab DNA-storage success has been claimed.**

## Objective and evidence gate

Demonstrate end-to-end recovery of the same frozen, non-biological digital payload through
**OligoArk encoding → physical oligo synthesis → independent sample preparation → physical sequencing → preprocessing → OligoArk recovery → exact SHA-256 match**.
Success requires verified raw lab reads, ordering/lot provenance, and independently verified
recovery of the entire source payload. The pristine software round trip is **not** physical evidence.

## Reproducible preflight

- Source: exactly 4,096 reproducible, non-biological bytes generated by
  `benchmarks/run_physical_pilot_preflight.py`; do not substitute real user data.
- Profile: `oligoark-152-compact-v3`; hybrid XOR/fountain redundancy; configured fountain
  redundancy 0.125. The normal archive framing, RS, CRC and SHA-256 checks remain active.
- Design core: at most 152 nt; GC 0.35–0.65; maximum homopolymer 4. Exact actual number of
  strands, lengths, index distribution, checksum, and FASTA/CSV must be taken from the
  **passing workflow's artifact**, never estimated as verified counts.
- Provisional provider sequence: up to 20 nt 5' primer + 152-nt OligoArk core + 20 nt 3'
  primer = **up to 192 nt**. This is a design envelope, **not approved primer sequences**.
  Provider and sequencing partner must review primer specificity, adapter/index compatibility,
  off-target priming, secondary structures and platform read length before final FASTA order.
- Command: `python benchmarks/run_physical_pilot_preflight.py --output physical-pilot-results`.
  See [GitHub Actions software preflight](../.github/workflows/physical-pilot-preflight.yml).
- Output: `pilot.bin`, `bundle/{archive.json,manifest.json,oligos.csv,oligos.fasta}`,
  `recovered-software.bin`, and `preflight-report.json`. All contain **software-only**
  evidence. Snapshot the exact commit, artifact checksum and tool versions.

The preflight checks original source SHA-256 against manifest and summary, exact clean
software recovery, strand count and uniqueness, FASTA/CSV agreement, strand alphabet,
length, GC constraints, and homopolymer constraint. A passing run does not confirm
PCR/primer compatibility, vendor manufacturing acceptance, sequence representation,
physical sequencing quality, or indel robustness.

## Sample design and controls

- Freeze payload bytes and original SHA-256 **before order**. Hash both the complete
  order FASTA and the codec-core FASTA and record exact nucleotide sequences and lot IDs.
- Request supplier QC / representation metrics, DNA quantity, synthesis technology,
  actual primer/adaptor sequences, and lot traceability.
- Prepare two independently handled technical replicates (OA-P1 and OA-P2), report each
  separately. If feasible, arrange independent synthesis lots in a later confirmatory run.
- Include a **no-OligoArk/no-template negative sequencing control** (OA-NEG) and an
  independently characterized known-sequence positive control (OA-POS).
- Preserve blinded analysis as far as possible: a decoder should consume trimmed reads
  plus normal OligoArk archive metadata, never use the hidden original payload or designed
  reference oligos to manually repair individual reads.
- Record sample/aliquot/barcode identity, chain of custody, instrument/run IDs, primer
  design, PCR cycles, read quality and contamination metrics, demultiplex commands and
  software versions.

## Sequence processing and acceptance

1. Retain **unaltered raw FASTQ** and checksums; create versioned derivatives for QC.
2. Demultiplex using recorded sample indexes; trim **documented** flanking primers/
   adapters; orient reads to the codec core; remove non-ACGT reads according to a frozen,
   reported quality rule. Record read counts at each stage.
3. Recover each replica independently using
   `python benchmarks/run_wetlab_validation.py recover BUNDLE REPLICA.fastq.gz OUTPUT.bin`.
   This uses original archive metadata and the configured reconstruction fallback.
4. Calculate `sha256sum` of each recovered file independently and compare to the
   pre-order original source hash; archive every exception/time-out, not merely successes.
5. Reanalyze independent fixed downsample subsets at **1, 5, 10, 20 reads/strand** when
   measured coverage permits. Fix random seeds; report full negative results and recovered
   source digests. Do not call an unavailable depth a failure or successful trial.
6. **PASS** only for a replicate with documentary evidence of actual oligo synthesis,
   sequencing data, and **byte-for-byte complete SHA-256-identical** recovered payload.
   Missing laboratory metadata, a simulation-only FASTA, a partial reference match,
   or a clean synthetic round trip is never a physical-storage PASS.

## Known risks and decision gates

- 10 MiB 152-nt indel-only codec trials historically failed under timeout; do not
  extrapolate from clean pilot recovery to strong indel tolerance.
- The 100 MiB four-method benchmark is incomplete. Physical pilot comparisons cannot
  be aggregated with unrelated simulations or reference-level sequencing benchmarks.
- Primer sequences, full oligo length, GC and homopolymer checks **must be re-evaluated
  on the final provider-ready full strands**, not only the OligoArk cores.
- If provider length or amplification requirements fail, revise design, generate a
  **new versioned bundle**, freeze its **new SHA and order manifest before purchase**,
  and retain the former version as superseded rather than changing the existing record.
- Synthesis batch, sequencing run, FASTQ, actual cost and provider turnaround remain
  **unavailable** until an external laboratory completes and documents its work.
