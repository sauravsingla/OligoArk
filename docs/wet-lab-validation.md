# OligoArk wet-lab validation protocol

## Status

**Prepared, not executed.** This document and the accompanying scripts define an executable
handoff for a laboratory. They are not evidence that OligoArk DNA has already been synthesized
or sequenced.

A true end-to-end claim requires the same OligoArk-generated oligos to pass this chain:

**payload → OligoArk encode → physical synthesis → storage → sequencing → preprocessing →
OligoArk reconstruction → exact SHA-256 verification.**

## 1. Pilot payload and success criterion

Start with a small heterogeneous pilot payload that is cheap enough to synthesize in full.
A practical first pilot is 4–16 KiB. Freeze the payload before ordering oligos and record its
byte size and SHA-256 digest in the experiment manifest.

The final pass/fail criterion is binary: the recovered payload SHA-256 must equal the frozen
source SHA-256. Partial strand reconstruction, high sequence similarity, or recovery of most
bytes is not archive success.

## 2. Generate the synthesis bundle

From the repository root:

    python benchmarks/run_wetlab_validation.py prepare pilot.bin \
      --output wetlab-bundle \
      --profile oligoark-200 \
      --scheme hybrid \
      --fountain-redundancy 0.125

The bundle contains oligos.fasta with synthesis core sequences, oligos.csv with per-oligo
metadata, archive.json with the exact recovery metadata, and manifest.json with source digest,
codec configuration, controls, read-depth plan and claim scope.

The default pilot uses the compact 200-nt software profile, Reed-Solomon protection, XOR
parity and fountain redundancy. The generated strands must be reviewed against the synthesis
provider's current acceptance rules before ordering.

Provider-specific primers, adapters, barcodes or flanking sequences are not part of the
OligoArk codec core. If the provider requires them, record the exact sequences and positions
in the experiment record and remove them during read preprocessing before OligoArk recovery.

## 3. Synthesis and storage record

Order the complete oligo set from oligos.csv or oligos.fasta. Preserve the provider order ID,
lot/batch ID, synthesis technology, delivered amount, provider QC report and any sequence
changes or rejected oligos.

Keep at least two independently handled aliquots when feasible so the recovery result is not
based on a single preparation. Record storage start/end dates, packaging/container, and the
laboratory's chosen storage conditions. OligoArk does not infer lifetime from this pilot.

A negative control containing no OligoArk library and a known-sequence positive control should
travel through the sequencing workflow.

## 4. Sequencing plan

Sequence the OligoArk library using the lab's chosen platform. Preserve the raw read files and
run metadata. Evaluate recovery at fixed read-depth targets of **1, 5, 10 and 20 reads per
designed strand** when the data allow it. Report the sampling seed whenever reads are
down-sampled.

For a stronger result, repeat the experiment with at least two independently prepared
technical replicates. Do not combine replicates before reporting whether each one passes the
SHA-256 gate.

## 5. Preprocessing contract

OligoArk recovery accepts FASTA/FASTQ, optionally gzip-compressed. Before recovery:

1. demultiplex using the sequencing provider's standard procedure;
2. remove documented adapters, primers and barcodes added outside the OligoArk core;
3. orient reads to the OligoArk core-strand direction and document reverse-complement logic;
4. remove reads containing unsupported symbols after the lab's quality-filtering policy;
5. keep the commands, tool versions and parameters used to create the final read file.

Do not use the unknown source payload or reference oligo sequence to edit reads manually.

## 6. Recover and verify

Run:

    python benchmarks/run_wetlab_validation.py recover \
      wetlab-bundle preprocessed.fastq.gz recovered.bin

The command first attempts direct frame decoding and exact archive recovery. If required, it
uses OligoArk's deterministic trace-consensus reconstruction. The recovered bytes are accepted
only if their SHA-256 digest exactly matches the digest stored in archive.json.

On success the bundle receives recovery-report.json. Keep that report together with raw
sequencing files, preprocessing commands, provider metadata and the exact OligoArk commit.

## 7. Evidence classes

| Evidence | What it proves | Current status |
| --- | --- | --- |
| Software channel benchmark | Codec/system behavior under controlled simulated faults | Available |
| External published physical reads | Reference-strand reconstruction on data generated by others | Available |
| Prepared OligoArk synthesis bundle | Lab-executable experiment design | Available in this PR |
| OligoArk synthesis + sequencing + exact archive SHA | True end-to-end physical OligoArk storage | **Not yet executed** |

A README or paper may move the final row to PASS only after the physical experiment has
actually been executed and the final recovered payload passes the SHA-256 gate.

## 8. Minimum experiment record

For reproducibility retain the repository commit, source SHA-256, manifest.json, archive.json,
ordered oligo files, provider/order/batch details, synthesis QC, storage dates/conditions,
sequencing platform/run IDs, raw read checksums, preprocessing commands/tool versions,
down-sampling seeds, read-depth results, replicate identity and recovery-report.json.
